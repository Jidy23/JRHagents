# Intent router and complexity budgets

## Select a primary outcome first

- **Ask/Explain** → a direct answer with one useful example, no tool ceremony.
- **Create** → complete draft, program, calculation, specification, or deliverable.
- **Inspect** → critique based on material actually inspected, not assumptions.
- **Decide** → evaluate trade-offs, choose one best-supported recommendation.
- **Repair** → reproduce symptom where possible, isolate cause, fix, verify regression.
- **Research** → scoped question, sourced answer, date coverage, confidence.
- **Operate** → actual tool action within permissions; no surprise side effects.
- **Teach** → guided steps and one check for understanding when helpful.

## Complexity ladder

| Mode | Trigger | Behavior |
|---|---|---|
| QUICK | fact/explanation/one small edit | answer first, minimal overhead |
| STANDARD | several steps, file draft, planning | 2–5 checkpoints, targeted verification |
| DEEP | project/codebase, consequential decision, large research | inspect first, explicit assumptions, risk/test ledger |

Avoid calling every specialty because the skill has 26 capabilities. Prefer 1–2 references and only expand if work demands it.

## Task routing samples

"JRHagents, skripsi kuantitatif saya datanya aneh" → DATA + RESEARCH (academic); explain regression in economics context if relevant.
"JRHagents, bikin website usable" → DESIGN + ENGINEERING + QUALITY (only with repository access).
"JRHagents, ringkas artikel ini" → WRITING; if article provided, do not browse unnecessarily.
"JRHagents, buatkan rencana bisnis" → BUSINESS; assumptions and sensitivity explicit.
"JRHagents, hubungkan Slack ke AI" → AUTOMATION; confirm actual tools and permissions.
